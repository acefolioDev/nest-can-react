# Agent Guide

## Common commands (core)

| Task | Command |
| --- | --- |
| Build / typecheck | `npm run build` (`tsc -p tsconfig.json` with `strict`) |
| Dev bundler | `npm run bin:dev` (alias of `node bin/nest-can-react.mjs dev`) |
| Release build | `node bin/nest-can-react.mjs build` |

There is no separate lint script; `tsc --strict` is the typecheck gate.

## Examples

Each example under `examples/<adapter>/` is a standalone Nest app that depends on
the workspace copy of `nest-can-react` (`"nest-can-react": "file:../.."`):

- `npm install` (in the example dir)
- `npm run view:dev` — starts the RSC dev bundler (HMR hub on :9101, client on :9102)
- `npm run start:dev` — runs the Nest host (Express or Fastify) on :3000

Run `view:dev` and `start:dev` in two terminals. The host reads generated
React refs from `src/react-pages.ts` (do not hand-edit; it is regenerated by
the bundler when page files change).

## Notes

- HTTP response normalization across adapters lives in `src/nest/response-utils.ts`.
- Redirect status codes live in `src/data/context.ts` (301, 302, 303, 307, 308).
- Redirect handling is implemented in `src/flight/handle-request.ts` (single render
  is aborted and a 3xx with `location` is written to the underlying Node response).
